# DualShield v13.19 — more security for T and P
1. multi/node_watch.py: baseline of a clean node, then NODEWATCH_ALERT for: new listening port, new uid-0 account, changed authorized_keys / cron / systemd units / sudoers, /etc/ld.so.preload (rootkit hook), new kernel module, new setuid program. Each finding once; `--accept` after your own change; baseline HMAC-signed when SELFGUARD_KEY is set. D reads the log through the signed agent (log name "nodewatch"). Tests: python3 multi/test_node_watch.py (14).
2. multi/harden_node.sh [apply|undo|status] [--dry-run] [--ssh-hardening] [--ssh-keys-only]: kernel settings, agent port 8800 reachable only from D at firewall level, auditd rules (code, sshd_config, ld.so.preload, sudoers, keys, module loads, firewall tools), file permissions, optional SSH hardening (never default: T's SSH is the brute-force demo bait). `undo` removes exactly what it wrote. Always run `--dry-run` first.
3. apply_v13_19.py starts node_watch from start_T.sh / start_P.sh, adds the "nodewatch" log to the agent and a node_watch line to check_T.
Honest limits: node_watch and harden_node were tested with stand-in files / dry-run, not on a real T/P yet; root can still stop node_watch (D then sees the node as SILENT); first start must be on a CLEAN node because that becomes the baseline; --ssh-keys-only locks out password login, put your key in first.
Install (after v13.16): unzip, python3 apply_v13_19.py, sudo multi/harden_node.sh apply --dry-run, then apply.
